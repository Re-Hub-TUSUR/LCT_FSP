# ATS Connector Layer

Работодатель опрашивает внешнюю ATS и получает решение по нашим фильтрам. Банк кандидатов
платформы, матчинг и лента этот поток не читают и не пишут. Внешний отклик не создаёт
пользователя KADRY.

Живого вендора в поставке нет. `ATS_MODE=mock` — три демо-отклика внутри процесса.
`ATS_MODE=fixture` — тот же протокол на JSON с другими именами полей. Когда появится ATS
с документацией API, добавляется один адаптер в `backend/app/integrations/ats/` и значение
`ATS_MODE`. Пайплайн и таблицы не меняются.

## Что видит домен

Протокол `AtsProvider`:

- `poll(cursor)` — отклики с прошлого курсора; тот же курсор возвращает те же события;
- `write_tag`, `write_note`, `write_score` — обратная запись;
- нормализованные кандидат, вакансия и отклик: навыки, опыт, город, текст резюме,
  обязательные навыки, вилка.

DTO конкретного провайдера остаются в его папке. `app/services/ats.py` и
`app/services/ats_pipeline.py` их не импортируют.

Курсор хранится на подключении компании (`ats_connections`). Повторный опрос того же
события не ставит второй разбор: уникальны подключение, провайдер и внешний id события.

## Фильтры

`ScreeningPipeline` получает уже нормализованную пару. Стадии не знают провайдера:

- жёсткие условия — обязательные навыки, потолок вилки, город;
- правила скоринга и причины, версия модели `rules-1`;
- пустые слоты эмбеддингов и LLM.

Решение: `pass`, `reject` или `review`. В результат пишутся score, decision, reasons,
matched skills, missing skills, model version и время.

Файл PDF или DOCX, если адаптер его приложил, читает `app/services/resume_text.py`.
Структурированные навыки парсер не вызывают.

## Очередь

Строки `screening_jobs` в PostgreSQL. Фоновый цикл в процессе API, как оповещения
сохранённых поисков, раз в `ATS_POLL_SECONDS` (0 — цикл выключен). Кнопка «Опросить»
в кабинете делает тот же проход сразу.

После разбора Mock сохраняет тег `kadry:pass|reject|review`, заметку с причинами и оценку.
Адаптер живого ATS сам выбирает метод своего API для этих трёх записей.

## Кабинет

Маршруты работодателя `/api/v1/ats/connection`, `/api/v1/ats/poll`, `/api/v1/ats/applications`.
Страница — «ATS» в шапке кабинета. Сначала нужен профиль компании.
