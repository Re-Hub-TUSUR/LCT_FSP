# Профиль кандидата

Резюме, то, как карточку видит работодатель, и связь с ФСП. Экраны: П-К-01, П-К-02, П-К-13, П-К-14.

## FR-К-01. Резюме по форме

**Приоритет:** MVP · К5 · **UC:** UC-К-02

**Правило.** Кандидат заполняет резюме: имя, специализацию, стек, стаж, город, формат работы. Почта берётся из аккаунта. Ожидаемая зарплата необязательна. Сохранение не ставит грейд.

**Строки UI:** «Сохранить резюме».

## FR-К-02. PDF с автораспознаванием

**Приоритет:** MVP · К5 · **UC:** UC-К-01

**Правило.** Кандидат прикладывает PDF или DOCX. Если задан ключ модели, текст разбирается и поля формы заполняются. Кандидат проверяет их перед сохранением. Без ключа загрузка резюме недоступна, форма заполняется вручную.

## FR-К-03. Грейд из резюме — только текст

**Приоритет:** MVP · К2 · **UC:** UC-К-01

**Правило.** То, что написано в резюме, не становится категорией. Категорию ставит только засчитанный тест.

## FR-К-04. Второе резюме

**Приоритет:** MVP · К2 · **UC:** UC-К-03

**Правило.** У кандидата может быть второе резюме другой профессии. Оно не становится основным само. Категория и кулдаун ведутся по специализации.

## FR-К-05. Карточка без контактов

**Приоритет:** MVP · К5 · **UC:** UC-К-04

**Правило.** До принятия приглашения работодатель не видит почту и телефон. Кандидат может скачать своё резюме.

## FR-К-06. Что видно в банке

**Приоритет:** MVP · К5 · **UC:** UC-К-21

**Правило.** В банке работодатель видит имя, специализацию, стек, город, формат, ожидаемую зарплату, если она указана, балл теста и достижения ФСП, которые кандидат не скрыл. Контактов нет.

## FR-К-07. Пауза поиска

**Приоритет:** MVP · К1 · **UC:** UC-К-22

**Правило.** Статус «Не ищу работу» убирает профиль из банка и ленты. Уже открытые приглашения и чаты остаются. Возврат к поиску снова показывает профиль.

**Строки UI:** «Не ищу работу».

## FR-К-08. Согласие при регистрации

**Приоритет:** MVP · К5 · **UC:** UC-О-02

**Правило.** Регистрация требует согласия на обработку данных. Без отметки аккаунт не создаётся. Отдельного согласия на запись экрана нет: записи теста нет.

## FR-К-09. Связь с ФСП

**Приоритет:** MVP · К1 · **UC:** UC-К-23, UC-К-25

**Правило.** Кандидат связывает профиль со своим ID участника ФСП. Сейчас реестр и вход эмулируются внутри API (`FSP_ID_MODE=mock`). Достижения подтягиваются по запросу кандидата. Отвязка убирает импортированные результаты и звания. Одна учётная запись ФСП — один аккаунт платформы.

**Строки UI:** «Связать с ФСП», «Отвязать».

## FR-К-10. Достижения ФСП на карточке

**Приоритет:** MVP · К1 · **UC:** UC-К-23

**Правило.** На карточке видна лучшая строка: дисциплина, соревнование, место, год. Полный список открывается вместе с профилем. Пустой реестр ошибкой не считается.

## FR-К-11. Нет истории ФСП

**Приоритет:** MVP · К5 · **UC:** UC-К-24

**Правило.** Если связи нет или история пуста, карточка не получает ни бонуса, ни штрафа. Кандидат видит, что истории пока нет.
